# Research Shrinks MIRAGE Into a Buildable Honeypot

MIRAGE is buildable by a 3-4 person team on a 16 GB M4, but only after the original technical report's heaviest and most fashionable choices are replaced: the research supports a thin Cowrie fork with a per-command policy gate, a deterministic-first responder with a bounded 4B-9B local model behind it, a contextual bandit instead of DQN/PPO, rules plus gradient-boosted trees instead of ET-BERT and E-GraphSAGE, an IOC graph with Leiden clustering instead of a GNN correlator, and a single-binary pipeline (Vector, NATS JetStream, a Python normaliser, ClickHouse, Parquet) instead of Kafka + OpenSearch + MinIO. Ten specific claims in the original report are contradicted or narrowed by primary sources. The "99.2% of honeypot traffic is scanning" figure does not appear in the paper it is attributed to; the source says about 9.8% of sessions were effective, so roughly 90% scanning. ET-BERT's ~97% accuracy collapses to 28% under a per-flow split. LogPrécis tags seven tactic-level labels from 360 sessions, not techniques, and predates the ATT&CK v19 split of Defense Evasion. Flower's SecAgg+ runs only on the deprecated legacy workflow API and its differential privacy is still labelled "preview". MinIO's community repository is archived. The closest published design to MIRAGE's router, HydraPoT (October 2026, MIT-licensed code), exists and should be read before a line of the responder is written. Two capabilities have no reusable base at all, a permissively licensed query-level database decoy and a labelled human/bot/LLM-agent dataset, so those are build-and-generate items rather than adopt items.

**How to read the evidence grades.** Every claim below carries one of five tags. **[V+]** means confirmed in the dedicated primary-source verification pass of 11 November 2026 (arXiv API and PDF text, Zenodo API, GitHub API and source at HEAD, PyPI, attack.mitre.org); where that pass conflicts with another note, it wins and the conflict is stated. **[V]** means a researcher opened the primary page, paper text, API or source file and read the claim there. **[A]** means abstract, landing page or README only. **[S]** means a search snippet or a secondary source such as another paper's related-work section. **[E]** means an engineering inference or estimate by the research team, not a published result. Claims that rested only on recollection were left out of the body and are listed in the final section on what remains unverified.

The 99.2% correction matters beyond citation hygiene. With a HoneyLLM-style scanner filter, capacity planning should assume roughly one session in ten reaches the LLM path, not one in a hundred **[E]**. HoneyGPT's replay corpora give the stricter pre-login view: 7,374 effective sessions out of 1,261,689 attacks (0.58%) and 2,479 out of 5,099,153 (0.049%), ratios derived from its Table III **[V]** ([HoneyGPT arXiv 2406.01882](https://arxiv.org/pdf/2406.01882)). AdvancedShelLM's 14-day deployment saw 148,850 sessions of which only 150 were interactive **[A]** ([arXiv 2606.27990](https://arxiv.org/html/2606.27990v1)). The "data desert" is real; the specific 99.2% number is not.

## Fork Cowrie at one file; write the HTTP and database decoys

### Cowrie is the only SSH base worth forking

Cowrie is BSD-3-Clause, shipped v3.1.6 on 9 November 2026 after near-weekly releases since July, and publishes amd64 and arm64 images **[V]** ([cowrie API](https://api.github.com/repos/cowrie/cowrie), [CHANGELOG](https://github.com/cowrie/cowrie/blob/main/CHANGELOG.rst), [Docker Hub](https://hub.docker.com/v2/repositories/cowrie/cowrie/tags?page_size=3&ordering=last_updated)). OpenCanary (BSD-3) is the other actively maintained permissive base, but it is low-interaction and its Docker images need Linux host networking **[V]** ([opencanary README](https://github.com/thinkst/opencanary/blob/master/README.md)). Everything else is a licence or maintenance problem for an Apache-2.0 or MIT release: Beelzebub and T-Pot are GPL-3.0, Conpot and VelLMes GPL-2.0, qeeqbox/honeypots AGPL-3.0, shelLM CC BY-NC-SA 4.0, and Canarytokens a GPLv3 variant that defines derivative works "as broadly as copyright law allows" **[V]** ([beelzebub API](https://api.github.com/repos/beelzebub-labs/beelzebub), [qeeqbox API](https://api.github.com/repos/qeeqbox/honeypots), [shelLM LICENSE](https://github.com/stratosphereips/shelLM/blob/main/LICENSE), [canarytokens LICENSE](https://github.com/thinkst/canarytokens/blob/master/LICENSE)). Galah is Apache-2.0 but has had no push since July 2025, and DECEIVE is MIT but self-described as proof-of-concept **[V]** ([galah API](https://api.github.com/repos/0x4D31/galah), [DECEIVE README](https://github.com/Cisco-Talos/DECEIVE/blob/main/README.md)). GPL projects can still run as separate unmodified containers whose logs MIRAGE consumes; their code and route packs cannot flow into the repository **[E]**.

Cowrie has no pre-execution hook: output plugins receive events only after the fact **[V]** ([EVENT_PIPELINE.rst](https://github.com/cowrie/cowrie/blob/main/docs/EVENT_PIPELINE.rst)). The verification pass against HEAD `ea9513e` settles where the gate goes, and it corrects the earlier note that suggested overriding `getCommand` in a protocol subclass. The minimal fork touches **`shell/honeypot.py` only**: put the policy gate between `bashparser.evaluate` and `_run_expanded` (lines 991-993) or at the top of `_run_expanded` (line 1154), and replace the command-not-found branch at lines 1215-1239 with the LLM fallback **[V+]** ([cowrie/cowrie](https://github.com/cowrie/cowrie)). Three caveats come from the same source read. First, `sudo.py`, `busybox.py` and `shell/command.py` (`exec_command`) call `getCommand`/`call_command` directly and bypass `_run_expanded`, so a gate that must cover commands launched by other commands also needs a change in `shell/protocol.py`. Second, the dispatch path is already Deferred-driven, so the policy call must be a non-blocking Twisted client (`treq` or `Agent`); a blocking `requests` call stalls every session. Third, older notes about Cowrie internals are wrong because the shell was rewritten around a Lark grammar and a Deferred trampoline; pin the fork to a release tag **[V+]**.

Cowrie's own `llm` backend is not the fallback MIRAGE wants. It is a parallel backend that sends every line to the model, has no fake filesystem, never updates `cwd` from "/", and keeps only the last 10 history lines **[V+]** ([llm/protocol.py](https://github.com/cowrie/cowrie/blob/main/src/cowrie/llm/protocol.py)). The reusable piece is `LLMClient.get_response(prompt) -> Deferred[str]` in `llm/llm.py`, an OpenAI-compatible async client. For state, `HoneyPotFilesystem` is copy-on-write per session with no change-event hook, but all mutations pass through about a dozen methods (`mkfile`, `mkdir`, `write`, `remove`, `rename` and so on) that a state manager can wrap **[V+]**.

One licence trap sits inside Cowrie itself. `src/cowrie/vendor/ja4/` carries `ja4h.py`, `ja4x.py` and `ja4ssh.py` under FoxIO License 1.1, which is non-commercial and excludes hosted or managed-service use; there is no config switch, and a clean fork has to delete `vendor/ja4/`, `core/fingerprint.py` and the two call sites in `ssh/forwarding.py` and `ssh_proxy/protocols/port_forward.py` **[V+]**. JA4 for TLS clients is BSD-3; the rest of JA4+ is FoxIO 1.1 **[V]** ([FoxIO License FAQ](https://github.com/FoxIO-LLC/ja4/blob/main/License%20FAQ.md)). HASSH, which Cowrie logs in `cowrie.client.kex`, is unaffected.

Default configuration is the cheapest tell to remove. Cowrie HEAD still ships hostname `svr04`, default user `phil`, and an `ssh -V` string (OpenSSH 7.9p1) that contradicts its own 9.2p1 wire banner **[V]** ([cowrie.cfg.dist](https://github.com/cowrie/cowrie/blob/main/src/cowrie/data/etc/cowrie.cfg.dist)). The deeper weakness is architectural. Bitter Harvest identified 7,605 honeypot instances with one probe packet at an equal error rate of 0.0183, exploiting transport-layer deviations of Twisted Conch from OpenSSH (for example random versus NULL KEXINIT padding), and its authors call this a "class break" that patches cannot fix **[V]** ([USENIX WOOT 2018](https://www.usenix.org/system/files/conference/woot18/woot18-paper-vetterl.pdf)). Whether current Cowrie still fails those exact probes was not checked. MIRAGE should treat a real OpenSSH front end proxying to the emulation as the deployment-phase answer **[E]**.

### No reusable HTTP or database base exists

Galah and Beelzebub are both Go, so neither is a base for a FastAPI decoy; their patterns are the asset. Galah contributes a strict JSON response contract (`{"headers": ..., "body": ...}`) and an SQLite response cache; Beelzebub contributes "static regex routes first, LLM only on the catch-all", guardrail prompts and per-IP rate limits **[V]** ([galah config.yaml](https://github.com/0x4D31/galah/blob/main/config/config.yaml), [Beelzebub configuration reference](https://docs.beelzebub.ai/reference/configuration)). Galah's cache key is `port + "_" + URL`, which ignores method and body **[V]** ([cache.go](https://github.com/0x4D31/galah/blob/main/internal/cache/cache.go)); MIRAGE should key on port, method, normalised path and query, body hash and a header subset **[E]**. Honeyval (Google Research, arXiv 2605.29963, Apache-2.0 code) is the evaluation harness to adopt for the HTTP tier: 16 backend applications with AI hacking agents pursuing verifiable exploit goals **[V+]** for existence and licence, **[A]** for results ([arXiv](https://arxiv.org/abs/2605.29963), [google-research/honeyval](https://github.com/google-research/honeyval)).

The database tier is the largest unbudgeted build item. None of the surveyed projects offers a permissively licensed, post-authentication, query-level emulation: qeeqbox captures credentials under AGPL, Beelzebub's PostgreSQL decoy asks an LLM to emit wire-format bytes "where possible", and VelLMes' LLM MySQL shell is GPL-2.0 **[V]** ([qeeqbox README](https://github.com/qeeqbox/honeypots/blob/main/README.rst), [tcp-5432-postgresql-llm.yaml](https://github.com/beelzebub-labs/beelzebub/blob/main/configurations/services/tcp-5432-postgresql-llm.yaml)). The sound split is deterministic framing and handshake in code, with templates or the LLM supplying only result-set content as JSON that the code serialises **[E]**. LLMPot supports the principle from the ICS side: a byte-level ByT5-small fully fine-tuned on 1,600 captured request/response pairs reached 99.30% response validity, while a 1B chat model scored near zero and LoRA performed poorly **[V]** ([arXiv 2405.05999](https://arxiv.org/pdf/2405.05999)). Protocol-server libraries for MySQL and PostgreSQL were not researched and are the main open item for this tier.

### The bounded responder: copy HydraPoT's shape, not its hardware

The literature converged on one architecture between 2023 and 2026: a filter/router, a deterministic responder for simple or cached answers, a prompt creator, a system-state manager outside the prompt, a session-history curator, and the LLM last. The SoK states that "no comprehensive, easily configurable architecture that implements all these features exists as open source" **[V]** ([SoK](https://arxiv.org/pdf/2510.25939)). HydraPoT (arXiv 2610.27722, AINTEC 2026, MIT code) now fills part of that gap for SSH: a complexity evaluator assigns levels F0-F4 and routes to Cowrie, a local Qwen3.5-9B GGUF, or cloud DeepSeek-V4 Flash, with a per-session `SYSTEM_STATE` dictionary as the authoritative shared state **[V+]** ([arXiv](https://arxiv.org/abs/2610.27722), [repo](https://github.com/Kamolchanok-Saengtong/HydraPoT)). Two precisions from verification: the 72.6% reduction is in cloud-processed tokens (cost $1.98 to $0.54), not total tokens, and the local model ran on an RTX 4060, not a laptop. HydraPoT has no human study, no live deployment, no injection defence and no adaptive policy; those are MIRAGE's contribution space **[A]**.

The state design to adopt combines HoneyGPT's structured triple (terminal output, state delta, impact factor 0-4, with the state register never pruned) **[V]** ([arXiv 2406.01882](https://arxiv.org/pdf/2406.01882)) with AdvancedShelLM's out-of-prompt JSON filesystem and verifier-emitted patches **[V+]** for architecture ([arXiv 2606.27990](https://arxiv.org/abs/2606.27990)). HoneyGPT's code is public after all (`zyw-286/HoneyGPT`, built on Cowrie, BSD-3 per README badge), which corrects the literature note that found no repository **[V+]** ([repo](https://github.com/zyw-286/HoneyGPT)). AdvancedShelLM's code exists only behind an anonymised link, LLMHoney has no code, and Say Shibboleth's linked repository is empty **[V+]**.

Expectations should be modest. HoneyLLM's best model raised average effective-session length from 2.96 rounds (Cowrie) to 5.83 (GPT-4o) **[V+]**. VelLMes fooled about 30% of 89 human participants **[A]** ([arXiv 2510.06975](https://arxiv.org/abs/2510.06975)). AdvancedShelLM lifted unit-test pass rates from 78% to 98% yet deception "did not improve in proportion", and humans noticed uniform timing **[A]**. LLMHoney's 13-model benchmark shows why a deterministic layer must carry common commands: Gemma3-1B answered in 488 ms but hallucinated 25.9% of outputs, while Phi3-3.8B had the lowest hallucination rate (5.8%) at about 3.6 s **[V]** ([arXiv 2509.01463](https://arxiv.org/pdf/2509.01463)).

For the M4, the realistic band is 4B-9B models at 4-bit quantisation (Qwen3.5 4B/9B, Gemma 4 E4B, Phi-4-mini 3.8B are all in the Ollama library as of 11 November 2026) **[V]** for availability ([qwen3.5](https://ollama.com/library/qwen3.5), [gemma4](https://ollama.com/library/gemma4), [phi4-mini](https://ollama.com/library/phi4-mini)); every tokens-per-second figure found was secondary or estimated, so benchmark locally. Serve with `llama-server`, which offers per-request JSON-schema and GBNF constraints, prompt-prefix caching, slot pinning, `n_predict` caps, API keys and Prometheus metrics **[V]** ([llama.cpp server README](https://raw.githubusercontent.com/ggml-org/llama.cpp/master/tools/server/README.md)). Run it natively on macOS and reach it from containers at `host.docker.internal`; `mlx_lm.server` describes itself as "not recommended for production" **[V]** ([SERVER.md](https://raw.githubusercontent.com/ml-explore/mlx-lm/main/mlx_lm/SERVER.md)). Do not assume coder models are better: Otal and Canbaz judged CodeLlama and Codestral less suitable than Llama3-8B, and their fine-tune on 617 commands moved cosine similarity only from 0.663 to 0.695, with Cowrie output as ground truth, so the model learned to imitate Cowrie **[V]** ([arXiv 2409.08234](https://arxiv.org/html/2409.08234v2)). Generate ground truth from real containers instead, the Cannypot "Explorer" pattern **[A]** ([SmartData-Polito/cannypot](https://github.com/SmartData-Polito/cannypot)).

Because every input is hostile, treat the model as a zero-privilege text generator: no tools, no secrets in the prompt, schema-bounded output, hard caps on input length, tokens and wall-clock time, and per-session and per-IP budgets with a circuit breaker to emulator-only mode **[E]**, mapped to OWASP LLM10 "Unbounded Consumption" mitigations **[V]** ([OWASP](https://genai.owasp.org/llmrisk/llm102025-unbounded-consumption/)). Avoid LLM Guard and Rebuff; both repositories are archived **[V]** ([llm-guard](https://github.com/protectai/llm-guard), [rebuff](https://github.com/protectai/rebuff)). Llama Prompt Guard 2 (22M and 86M classifiers) is usable as an asynchronous session feature rather than a blocker, since a visible refusal is itself a tell **[V]** for the model card, **[E]** for the usage ([HF card](https://huggingface.co/meta-llama/Llama-Prompt-Guard-2-86M)). No paper reports a measured denial-of-wallet attack on an LLM honeypot, and no published design measures state-aware caching; the cache-key scheme (persona, normalised command, state fingerprint) is design inference **[E]**.

## A bandit with a safety mask replaces DQN and PPO

Every RL shell honeypot since Heliza uses the same small formulation: state is the attacker command or a command class, actions are allow, block, substitute, delay and insult, and the learner is tabular SARSA or Q-learning. Q-Cowrie (International Journal of Information Security, 2026) is still tabular: eight ATT&CK-stage states, alpha 0.1, gamma 0.9, 1,000 episodes, a Q-table warm-started from an empirical MDP over Cowrie logs **[V]** ([Waikato open copy](https://researchcommons.waikato.ac.nz/items/cfc0e5b5-0f3f-4434-9a55-458d98dafc92)). Its headline 94% and 80% figures are author-defined metrics, not engagement gains over Cowrie. HoneyIoT's PPO result came from 100 simulated sessions **[S]** ([WiSec'23](https://mcn.cse.psu.edu/paper/guan-chongqi/wisec23-chongqi.pdf)). Nothing in the literature justifies deep RL at hundreds to low thousands of informative sessions, and no paper benchmarks bandits against Q-learning or DQN for this task, so the recommendation is inference from off-policy-evaluation literature **[E]**.

The build order that follows: a rule policy with epsilon-greedy exploration over the allowed action set, logging context, action mask, chosen action and propensity from day one; then a contextual bandit; then offline sequential RL as an experiment only. Logged propensities are non-negotiable because bandit feedback reveals only the chosen arm's reward **[S]** ([arXiv 1612.00367](https://arxiv.org/pdf/1612.00367)). Vowpal Wabbit 9.11.9 (BSD-3, macOS arm64 wheels, `--cb_explore_adf` for changing action sets, built-in IPS/DR/MTR estimators) is the maintained choice; Open Bandit Pipeline (2023), SCOPE-RL (2023) and d3rlpy (March 2025) are stale and belong in a pinned Python 3.11 container if used at all **[V]** ([PyPI vowpalwabbit](https://pypi.org/project/vowpalwabbit/), [PyPI obp](https://pypi.org/project/obp/), [PyPI d3rlpy](https://pypi.org/project/d3rlpy/)). Safety rules belong in a deterministic mask outside the learner; `sb3-contrib` MaskablePPO implements this for simulator experiments **[V]** ([docs](https://sb3-contrib.readthedocs.io/en/master/modules/ppo_mask.html)).

Reward design is where prior work teaches most. RASSH and Cannypot rewarded session duration or command count, which rewards stalling **[S]** ([arXiv 2512.07827](https://arxiv.org/pdf/2512.07827)). Asguard made reward depend on state and action together (+1 for allowing a download command, -1 for allowing execution of a downloaded custom command), which is how "collect the payload but never run it" gets encoded, and deliberately dropped the insult and delay actions **[V]** ([SCITEPRESS 2021](https://www.scitepress.org/Papers/2021/107191/107191.pdf)). MIRAGE should pay for new techniques, new payload hashes and honeytoken touches, deduplicated by campaign, and charge for LLM tokens and risk events **[E]**.

Pre-training in CyberBattleSim or CybORG does not transfer. CAGE-4 and ORNL's Cyberwheel do have first-class decoy actions, but they answer "where to place decoys on a network", not "how to answer this command" **[V]** ([cage-challenge-4](https://github.com/cage-challenge/cage-challenge-4), [ORNL/cyberwheel](https://github.com/ORNL/cyberwheel)). No reusable Gymnasium environment that replays SSH sessions was found; MIRAGE builds one from public corpora, knowing that logged attackers reacted to Cowrie's behaviour rather than MIRAGE's **[E]**. Two CC BY 4.0 corpora feed it: the CyberLab honeynet dataset (Zenodo 3687527, about 50 nodes, May 2019 to February 2020) and the July 2026 corpus of 160 Cowrie instances (Zenodo 21260400: 50 days, 14 countries, 211M events, 38M sessions, 214k source IPs), whose persistence-enabled configurations are the only public data found on how filesystem persistence changes attacker behaviour **[V+]** ([Zenodo 3687527](https://zenodo.org/records/3687527), [Zenodo 21260400](https://zenodo.org/records/21260400)).

## Rules and boosted trees beat the proposed deep models

### Flow classification is a descriptor, not a detector

"The Sweet Danger of Sugar" (SIGCOMM 2025) shows the reported accuracy of pretrained traffic models is a split-leakage artefact. Beyond the ET-BERT collapse in the table above, frozen ET-BERT scores 10.9% accuracy / 6.7 macro-F1 per-flow on TLS-120, and removing sequence numbers, acknowledgement numbers and timestamps from the test set alone drops per-packet performance to 19.5 / 15.4 **[V+]** ([arXiv 2507.16438](https://arxiv.org/abs/2507.16438)). The same paper reports Random Forest, XGBoost and LightGBM on header features at 78.0-82.4 macro-F1 under per-flow splits, with RF training in about 22 seconds **[V]**. On a honeypot the case for a benign-versus-malicious flow model is weaker still, because everything inbound is unsolicited **[E]**. Flow features remain useful for tool fingerprinting and attack-type tags, for which Zeek and Suricata plus LightGBM suffice, trained on MIRAGE's own traffic because lab NIDS datasets generalise poorly across networks **[S]** ([arXiv 2205.04112](https://arxiv.org/pdf/2205.04112)).

### Tagging: LogPrécis for tactics, rules and retrieval for techniques

LogPrécis remains worth adopting as a free first signal, with its limits stated. Models `SmartDataPolito/logprecis` and `SmartDataPolito/SecureShellBert` are Apache-2.0; annotations are CC BY 4.0 **[V+]** ([repo](https://github.com/SmartData-Polito/logprecis), [HF org](https://huggingface.co/SmartDataPolito)). The licence files were added in a commit dated 11 November 2026; before that day the repository had none, and the CC BY licence does not cover the underlying HaaS session content **[V+]**. Its best configuration reaches token accuracy 0.912 but session fidelity only 0.669, and plain CodeBERT's 0.899 accuracy corresponds to macro-F1 of 0.624, so the "over 90%" headline hides weak minority tactics **[V]** ([arXiv 2307.08309v3](https://arxiv.org/html/2307.08309v3)). Its 130M-parameter encoder beat fine-tuned GPT-3 Davinci, a useful precedent for small models.

No off-the-shelf technique-level tagger for Linux shell sessions exists, and no public benchmark for one was found. The pragmatic stack is a regex rule layer on normalised commands, then retrieval over ATT&CK descriptions and Atomic Red Team commands with an LLM re-ranker cached per unique command, then a small encoder fine-tuned on MIRAGE's own emulation ground truth **[E]**. Planning numbers should come from the honest end of the range: GPT-4 labelling at 72.46% accuracy **[S]** ([Sabancı record](https://research.sabanciuniv.edu/id/eprint/49551/)), and SecureBERT macro-F1 of 0.44 rising to 0.66 with augmentation, against 0.92-0.97 claimed on authors' own augmented splits **[S]** ([arXiv 2507.16852](https://arxiv.org/html/2507.16852v1), [arXiv 2403.03267](https://arxiv.org/abs/2403.03267)). Every label and prediction must store its ATT&CK version: v20.1 is current (v20 live from 13 October 2026), Enterprise now has 15 tactics, and Caldera ability tactics are free-text strings that nothing maps to the v19+ names **[V+]** ([ATT&CK versions](https://attack.mitre.org/resources/versions/), [apache/caldera](https://github.com/apache/caldera)).

### Session, anomaly, agent and campaign models

For scanner, scripted-bot, human and LLM-agent classification, the literature is mostly unsupervised clustering; no peer-reviewed supervised classifier with metrics and no public labelled dataset was found. Start with deterministic rules and gradient-boosted trees on timing, keystroke and fleet-novelty features **[E]**. For anomaly detection, log-anomaly studies found simple methods such as kNN outperforming deep models in accuracy and time **[S]** ([ICSE 2024](https://conf.researchr.org/details/icse-2024/icse-2024-research-track/21/Deep-Learning-or-Classical-Machine-Learning-An-Empirical-Study-on-Log-Based-Anomaly-)); first-seen counters plus Isolation Forest are the baseline, evaluated by analyst precision at k **[E]**. Reported 94-99% next-command accuracy reflects memorised botnet scripts, since LogPrécis collapses about 400,000 scripts into fewer than 3,000 fingerprints **[S]**, **[V]** for the fingerprint count.

LLM-agent detection has one in-the-wild method, Palisade's: prompt-injection canaries in the banner, command outputs and files, plus a latency test. It found **8 potential AI agents in 8,130,731 interactions** over about three months, and the authors call the timing analysis preliminary with false positives and evasion unaddressed **[V]** ([arXiv 2410.13919v2](https://arxiv.org/html/2410.13919v2)). The threshold wording differs between versions (1.5 s versus about 1.7 s), and most ordinary bots also answered inside it. Say Shibboleth (9 November 2026) reports 90% top-1 accuracy distinguishing 15 models and 92% identifying one of four harnesses, without needing a successful injection, but no code is available **[V+]** for existence and code status, **[A]** for numbers ([arXiv 2611.12386](https://arxiv.org/abs/2611.12386)). At roughly one agent per million sessions, canary compliance must be the high-specificity gate and timing only a ranking signal **[E]**. Prompt-injecting third-party agents is active manipulation of someone else's system and needs a legal and ethics view first **[E]**.

Campaign correlation should start as an IDF-weighted session-indicator graph (payload hash, download host, injected SSH key, command-sequence hash) with connected components on strong edges and Leiden on the weighted graph **[E]**. A practitioner write-up found shared HASSH the weakest link type, also present on about 120 unrelated addresses **[S]** ([write-up mirror](https://hackernews-dynamic.seasondane.workers.dev/news/48320615)). Edge tables in DuckDB or Postgres plus igraph are enough; Kuzu, the embedded graph database often suggested for this role, is archived (MIT, last push 2025-10-10) **[V+]** ([kuzudb/kuzu](https://github.com/kuzudb/kuzu)).

## A single-binary pipeline, a scripted lab, and a federation that picks one privacy tool

### Infrastructure sized to 16 GB

T-Pot states 16 GB RAM for a hive, equal to the whole laptop; Caldera recommends 8 GB or more; OpenCTI Core is documented at 8 GB or more **[V]** ([tpotce README](https://github.com/telekom-security/tpotce), [apache/caldera README](https://github.com/apache/caldera), [OpenCTI docs](https://docs.opencti.io/latest/deployment/overview/)). No primary idle-memory numbers were found for NATS, Vector, ClickHouse, Grafana or MLflow, so the laptop budget is an estimate to be measured with `docker stats` in week one **[E]**. The recommended chain is honeypot JSON logs, Vector 0.61 **[V]** ([releases](https://vector.dev/releases/)), NATS JetStream, a 200-400 line asyncio normaliser with pydantic models, ClickHouse capped in memory, Parquet for ML, and Grafana, organised into Docker Compose profiles so the `lab` and `llm` profiles never run together **[E]**. Faust should not be built on (its fork is rated inactive) and Bytewax is community-maintained since May 2025 **[V]** for repo banners ([faust-streaming](https://github.com/faust-streaming/faust), [bytewax](https://github.com/bytewax/bytewax)).

Align the canonical event to OCSF 1.9.0 (3 August 2026), which now carries an `ai_operation` profile and a `record_integrity` profile, and keep ECS dotted names as a projection for Sigma compatibility **[V]** ([ocsf-schema releases](https://github.com/ocsf/ocsf-schema/releases)). No published Cowrie-to-OCSF or Cowrie-to-ECS mapping was found; the mapping is a design proposal **[E]**. Cowrie's tree does contain `core/ocsf.py` and `core/cef.py`, whose contents were not read and should be checked before writing a mapper **[V]** for existence.

Sensing splits by host. Tetragon's docs say it cannot run on Docker Desktop for macOS, and Tracee recommends a Linux VM **[V]** ([Tetragon install](https://tetragon.netlify.app/docs/getting-started/install-docker), [Tracee mac docs](https://aquasecurity.github.io/tracee/dev/docs/advanced/mac)). On the Mac, published ports are NATed so honeypots see a gateway address, which makes the laptop wrong for any `src_ip` logic **[E]**. Containment on the VPS means an `--internal` honeypot network, default-deny egress, dropped capabilities and read-only root filesystems, with gVisor as the extra layer that needs no KVM **[S]** ([Northflank](https://northflank.com/blog/kata-containers-vs-gvisor)). Provider terms are a gating item: DigitalOcean's AUP forbids security or malware research "without DigitalOcean's prior written consent" **[V]** ([AUP](https://www.digitalocean.com/legal/acceptable-use-policy)). The Mac must never be internet-exposed.

### Ground truth from a scripted runner first, Caldera second

Caldera's canonical home is `apache/caldera` (Apache-2.0; latest release 5.3.0, 24 April 2025, with no newer tag) **[V+]**. It emits the needed record. `POST /api/v2/operations/{id}/event-logs` and `POST /api/v2/operations/{id}/report` (both POST, not GET) return per-link `attack_metadata.technique_id`, `tactic` and `technique_name` with `delegated_timestamp`, `collected_timestamp` and `finished_timestamp`; report steps use the different names `attack.*`, `delegated` and `run` **[V+]** ([operation_api.py](https://raw.githubusercontent.com/apache/caldera/master/app/api/v2/handlers/operation_api.py)). `delegated` is when the server queued the link, not when it ran, so label intervals should use collected-to-finished **[E]**.

Caldera targets endpoint post-compromise behaviour and is heavy, so the MVP for labelled SSH and HTTP sessions is a small scenario-runner container that plays YAML scenarios against the honeypot on an isolated network and writes its own label records before and after each step **[E]**. The documented pitfalls are concrete: Atomic Red Team commands can embed the ATT&CK ID itself, which had to be sanitised before inference **[S]** ([arXiv 2609.12841](https://arxiv.org/pdf/2609.12841)); some emulated attacks fail and labels must reflect that **[S]** ([LMDG, arXiv 2508.02942](https://arxiv.org/pdf/2508.02942)); and the team that designs the attacks also assigns the ground truth **[S]** ([arXiv 2606.18190](https://arxiv.org/html/2606.18190)). Split by scenario and by time, never by event; hold out whole techniques and attacker styles; report lab-only and wild results separately, because a model that separates "lab" from "wild" has learned the environment **[E]**.

### Federation: what Flower can and cannot do at 2-5 sites

Flower is at 1.43.0 (4 November 2026), the repository is now `flwrlabs/flower`, and the 1.36-1.43 series carries repeated breaking transport changes, so pin versions across sites **[V+]** ([PyPI flwr](https://pypi.org/pypi/flwr/json)), **[V]** for the changelog ([changelog](https://flower.ai/docs/framework/main/en/changelog/index.html)). The original report's "SecAgg+ and DP" pairing fails on API generations: SecAgg+ works only with the legacy workflow and legacy `flwr.server.strategy` classes, while the Message-API strategies hold the DP wrappers and robust aggregators (Krum, Bulyan, FedMedian, FedTrimmedAvg) **[V+]**. It also fails on mathematics. Robust aggregators must inspect per-client updates that secure aggregation hides **[S]** ([arXiv 2006.04747](https://pdf.arxiv.org/pdf/2006.04747)), and Krum's guarantee needs n >= 2f+3, so five sites to tolerate one bad one **[S]** ([arXiv 2608.04045](https://arxiv.org/pdf/2608.04045)).

The utility evidence is cautionary. In cross-silo FL, FedAvg "may underperform simple local training due to data heterogeneity" **[S]** ([NeurIPS 2022](https://proceedings.neurips.cc/paper_files/paper/2022/file/2788b4cdf421e03650868cc4184bfed8-Paper-Conference.pdf)). A September 2026 Scientific Reports study of low-client-count FL found SecAgg added about 49-106% training time without reducing final-model leakage, and record-level DP-SGD preserved utility best **[S]** ([Zenodo record](https://zenodo.org/records/23012579)). No study evaluates FL with DP against local-only training for intrusion detection at 2-5 clients, and none uses honeypot-derived data. MIRAGE should therefore run local-only, FedAvg/FedProx, personalised and centralised baselines per site, claim FL value only for recall on attack classes a site has not seen, use record-level DP-SGD through Opacus if DP is required, and not claim site-level DP **[E]**. Simulation on the laptop is supported through `flwr run` with the Ray backend on macOS, then Flower's Docker Compose setup for a multi-site rehearsal **[V]** ([Run simulations](https://flower.ai/docs/framework/how-to-run-simulations.html), [Docker Compose quickstart](https://flower.ai/docs/framework/docker/tutorial-quickstart-docker-compose.html)).

## What remains unverified

The verification pass itself left four items open: the AdvancedShelLM anonymised code link was not opened, so its contents and licence are unknown; LLMHoney's lack of a repository rests on the paper text and one search; HoneyGPT's licence comes from a README badge, not the LICENSE file; and the ATT&CK v20 date discrepancy (website 13 October 2026, STIX bundle tags 5 November 2026) is unresolved. The IEEE Xplore version of HoneyLLM was not checked, so the 99.2% correction rests on the author-hosted PDF.

Nothing was pulled, run or benchmarked. Every memory footprint, every tokens-per-second figure, the M4 fine-tuning time estimates, and arm64 availability of the `flwr/*`, Zeek and Suricata images are unmeasured. Whether Docker Desktop on macOS can pass the Metal GPU to Linux containers was not confirmed from a primary source; the plan assumes it cannot.

Several facts were recalled rather than opened and were excluded from the body or flagged where a recommendation depends on them. These include licences and multi-arch status of Vector (MPL-2.0), ClickHouse, OpenSearch, Grafana and MLflow; OCSF class UIDs and the Python OCSF model libraries; FastAPI and uvicorn default tells (`server: uvicorn`, `/docs`, `/openapi.json`); OpenCanary's service list and log schema; d3rlpy's FQE API; Bulyan's n >= 4f+3 bound; CAPEv2 host requirements; the GDPR Recital 49 anchor; and PyTorch Geometric's MPS support. CmdCaliper's licence, gating and Linux-shell transfer are snippet-level only.

Many cited papers were read only as abstracts or through the SoK: VelLMes, Honeyval and Say Shibboleth results, Magazov et al. (including the 71% backend-identification figure), the Weber et al. 52% believability figure, the Ozkok et al. model version, Heliza, RASSH, QRASSH, the Asgard 2022 journal numbers, the FL-IDS reviews, and all legal sources. Legal analysis for the team's own jurisdiction was not researched, and hosting-provider terms beyond DigitalOcean and a dated AWS snippet were not retrieved.

Four evidence gaps are structural rather than fixable by another search: no public benchmark for technique-level tagging of Linux shell sessions; no labelled human/bot/LLM-agent session dataset; no evaluated latency-shaping countermeasure for LLM shells; and no study of federated learning on honeypot-derived data. Protocol-server libraries for the database decoys and the exact latest patch versions of Kafka, NATS, Valkey, ClickHouse and Suricata still need a short check before pinning.

## Conclusion

The pattern across all ten corrections is the same: the original report chose components by reputation in adjacent fields, and the primary sources show each one either measured under a leaky protocol (ET-BERT), solving a different problem (CyberBattleSim, E-GraphSAGE), claiming a finer granularity than it has (LogPrécis), or unavailable in the proposed combination (Flower SecAgg+ with DP, MinIO). What replaces them is smaller and more defensible, and it moves MIRAGE's novelty to where the literature is empty. No published honeypot evaluates its response policy with off-policy estimation before deployment. None measures state-aware caching or latency shaping. None ships a labelled actor-type dataset. An isolated lab that emits per-step ground truth, a policy log with propensities, and a held-out-by-scenario evaluation would each be a first.

The second implication is about what to measure. The SoK's framing, that attacker cost and defender cost are the success indicators while believability and fidelity are diagnostics, combined with a roughly 90% scanner share, means MIRAGE should be judged on new techniques and artefacts captured per LLM token spent among the one-in-ten sessions that matter, and tested against LLM attack agents with verifiable goals rather than Internet noise. The week-one tasks are correspondingly unglamorous: measure container memory on the M4, benchmark two candidate models against real-container ground truth, strip the FoxIO code from the fork, and get hosting consent in writing.
